## 1. 這頁要回答的一個問題

> 這套系統做不到什麼？哪些環節必須靠人、靠實體資源、靠外部系統介入？

## 2. 一句話 Key Message

> Harness 能做的是「產出指引、追蹤狀態、判斷結果」——但 FEA 執行、原型製造、實測數據、供應商確認、量產驗證，這些都需要外力介入。

## 4. 主要內容

### A. Harness 能做 vs 需要外力

| Harness 做得到 | Harness 做不到 |
|:--------------|:-------------|
| 產出 Material Card + FEA 設定建議 | 實際執行 FEA/CFD 求解 |
| 產出 WI CAD 組裝指引 + BOM | 實際加工零件 + 組裝原型 |
| 產出測試計畫 + 自動 PASS/FAIL 判讀 | 實際執行 V-test + 收集量測數據 |
| 產出 DFM checklist + SOP 草稿 | 供應商工藝確認 + 現場驗證 |
| 產出 PPAP 文件包 + 缺口報告 | 客戶簽核 + 實體樣品 + 治具 |
| 計算 Cpk/Ppk + 製程能力判定 | 產線連續量測數據收集 |
| 追蹤 Gate 狀態 + 風險登記 | 管理決策 + 資源分配 |

### C. Handoff 協定

每個外力介入點都有明確的交接協定：

```
Harness 產出          外力執行            Harness 接收
─────────────  →   ─────────────  →   ─────────────
指引文件              物理動作             結果數據
(WI/MC/Plan)         (測試/製造)          (報告/量測值)
     │                    │                    │
     └────── 驗證 Gate 確認交接品質 ──────────┘
```

**規則**：
- Harness 產出的指引 = 外力的「輸入規格」
- 外力回傳的數據 = Harness 判讀的「輸入」
- Gate 是品質關卡——確認交接雙方都完成了自己的責任

### D. 分佈概覽

| Phase | 外力項數 | 性質 |
|:------|:---------|:-----|
| P4 PROVE | 2 項 | 模擬執行 + 材料驗證 |
| P5 BUILD | 3 項 | 供應商 + 原型製造 + Alpha 測試 |
| P6 HARDEN | 3 項 | Beta 原型 + 量測 + 供應商互動 |
| P7 SCALE | 5 項 | PV 測試 + SPC + PPAP + SOP + 移轉 |

**趨勢**：越往後段（P6-P7），外力介入越密集——這正是為什麼前端（P0-P3）值得多花時間做對。

## 6. 口條骨架（25 秒）

> 這一頁很重要——它說的是系統做不到什麼。左邊是 Harness 能做的：產出指引、追蹤狀態、判讀結果。右邊是一定需要人和實體資源的：跑 FEA、做原型、實測、跟供應商確認。中間這張表是 13 個明確的外力介入點，每個都有清楚的交接協定。注意一個趨勢：越往後段，外力介入越密集——這正好說明為什麼前端值得多花時間做對。
