# DK-01 — Auto-TRIZ 流程

> Step 0-5 閉環 + 多 TC 路由 + 停止條件 + 工程下游銜接。
> SSOT: `docs/_harness/auto_triz_strategy.md` §0-9 + `uml/02_main_flow.md` + `uml/05_multi_tc_strategy.md`。

---

## §1 三層工具嵌套

TRIZ 三大工具不是平行可替換的選項，而是**同一問題在不同解析度下的嵌套式收斂路徑**：

| 工具 | 解析度 | 角色 | 解決的是 | 產出 |
|:-----|:------|:-----|:--------|:-----|
| **TC** 技術矛盾 | 10x 鏡頭 | 外交官 | 參數間的 trade-off | 啟發性方向（候選原理） |
| **PC** 物理矛盾 | 100x 鏡頭 | 外科醫生 | 單一參數的自我對抗 | 決定性分割策略 |
| **SF** 質-場分析 | 手術刀 | 配方工程師 | 功能的物理實現 | 具體 F + S 結構 |

**兩種使用模式**：

| 問題類型 | 路徑 |
|:---------|:-----|
| **有矛盾**（改善 A → 惡化 B） | TC → PC → SF 嵌套主流程（§2-7） |
| **功能缺失**（做不到，但無副作用） | SF-only 快速通道（跳 TC/PC，§2 末段） |

## §2 入口判定

按子系統分別判定。同一產品的不同子系統可能處於不同 Level — 馬達子系統 Level B（已知 TC），電池子系統 Level A（只知道不滿意）→ 分別路由。

### §2.1 成熟度路由

| Level | 你能做到 | 路由 |
|:------|:--------|:-----|
| **C** | 連系統都描述不了 | 不適用 TRIZ → 替代框架（§2.2） |
| **A** | 能描述系統 + 知道不滿意，說不出 trade-off | 進 **Step 0** 發掘 TC |
| **B** | 能填完造句（§2.3） | 跳過 Step 0，直接 **Step 1+** |

### §2.2 Level C 替代框架

| 問題狀態 | 框架 | 推理邏輯 |
|:---------|:-----|:---------|
| 完全未知、找市場切入點 | Design Thinking / JTBD | 找用戶未滿足痛點 |
| 功能已定、結構耦合嚴重 | Axiomatic Design | 推理如何讓功能獨立 |
| 產品成熟、預測下一代 | System Evolution Trends | 系統演化路徑 |

### §2.3 Level B 造句驗證

> 「在 **[系統]** 中，為了 **[改善 A]**，會導致 **[B 惡化]**。」

此造句是 **Step 0 結束時的驗證檢查點**，不是入口閘門。Level A 完成 Step 0 後應能填完此造句再進 Step 1。

### §2.4 最小必要輸入

| 輸入 | 為什麼不能少 |
|:-----|:------------|
| 一個可描述的系統（誰對誰做了什麼） | 沒系統就沒 FA |
| 至少一個「不滿意」 | 沒痛點就沒矛盾 |
| 至少兩個相關物理量 | 一個變數 = 純最佳化，不需 TRIZ |

### §2.5 SF-only 快車道條件

當 Step 1 SF 診斷狀態為「缺失」或「不足」、且無副作用時：

```
Step 1 (FA+SF) → SF 標準解（76 解 5 大類）→ 科學效應 → Step 4 驗證
```

跳過 Step 2/3，直接用 76 標準解補全功能。詳見 DK-02 §5。

### §2.6 進入決策樹

```
你的問題是？
├─ 「動了 A 就壞 B」 → Step 0 或 Step 1
├─ 「東西壞了不知為何」 → Step 0（5Why）
├─ 「設計新東西，需求互相打架」 → Step 1
├─ 「功能做不到，無副作用」 → SF-only 路徑
├─ 「要某指標更好，無副作用」 → 不是矛盾，用 DOE/田口/ML
├─ 「不知該做什麼產品」 → TRIZ 不處理（用 DT/JTBD）
└─ 「降成本不降規格」 → 直接 Step 2（這就是 TC）
```

## §3 Step 0 — 問題定向

### §3.1 何時需要 Step 0

| 情境 | 5 Why | KT Is/IsNot | 跳過直入 TRIZ |
|:-----|:-----:|:----------:|:------------:|
| 客訴/現場問題，根因不明 | **必要** | 有對照組時 | — |
| 良率問題（A 線 vs B 線） | 可選 | **必要** | — |
| RD 設計新功能，已知要做什麼 | — | — | **直入** |
| 已知兩參數衝突，要找 Px | — | 可選 | **直入** |

### §3.2 5 Why 因果定向

從症狀往下挖到**可操作的因果節點**（5 分鐘內）。

```
症狀：馬達爬坡時異音
  Why1 → 齒輪嚙合不良
  Why2 → 齒輪間隙超標
  Why3 → 高扭矩下軸承變形
  Why4 → 軸承剛性不足
  Why5 → 為了減重選了輕量化軸承
        ▼
        初步 TC：剛性 vs 重量
```

**限制**：5 Why 假設因果是線性。TRIZ 矛盾常是環狀（A 致 B、B 加劇 A），所以 5 Why 只能**定向**，不能**定義矛盾**。到底層後必須交棒給 TC/PC。

### §3.3 KT Is / Is Not（選配）

**前提**：需要對照組。沒對照組跳過。

| 維度 | IS（有問題） | IS NOT（沒問題） | 獨特差異 |
|:-----|:------------|:----------------|:---------|
| What | 哪個產品/零件出問題 | 哪個類似的沒問題 | 兩者差異 |
| Where | 問題位置 | 沒發生的位置 | 位置獨特條件 |
| When | 何時開始 | 沒問題的時段 | 時間點變化 |
| Extent | 程度/頻率 | 在什麼程度內沒事 | 閾值邊界 |

### §3.4 KT → OZ-OT 銜接

```
Where IS vs IS NOT  → OZ（操作空間）
When  IS vs IS NOT  → OT（操作時間）
獨特差異            → Px 候選清單
```

### §3.5 決策閘門

| Step 0 結束狀態 | 路由 |
|:---------------|:-----|
| 根因鎖定 + 是物理參數 | 跳 Step 2 ⚠️ 跳步風險（建議產出後回補 Step 1） |
| 根因涉及組件交互 | Step 1 |
| 根因仍模糊 | CECA 因果鏈分析 → 重新判定 |
| CECA 後仍無法收斂 | §9 喊停決策 |

### §3.6 Step 0 不做什麼（與 KT 框架的關係）

舊版 DK-03 KT 決策框架（MUST/WANT/Adverse Consequences、7 大 WANT）已**完全移除**。Step 0 只用 KT 的 **Is/Is Not 差異分析**作為 OZ/OT 鎖定工具，**不做** MUST/WANT 評分。原因：SSOT (`auto_triz_strategy.md`) 不依賴 MUST/WANT 框架；TRIZ 收斂依賴的是 Px 與分離原理，不是加權打分。

## §4 Step 1 — 功能建模

Step 1 不需載入 KB，但產出是所有後續 KB 查詢的輸入。

### §4.1 三項必要產出

| 產出 | 格式 | 下游用途 |
|:-----|:-----|:---------|
| 組件交互圖 | 組件 →(功能)→ 組件，標記**有效/有害/不足/過度** | Step 2 TC 定義來源 |
| SF 診斷 | S1, S2, F + 狀態（無效/有害/不足/缺失） | Step 3d SF 路由、SF-only 入口 |
| 改善/惡化描述 | 自然語言 | Step 2 參數映射輸入 |

### §4.2 子系統邊界定義

- 圍繞 OZ（衝突點）建邊界，**不**按硬體零件劃分
- 從核心功能開始，**不**從 BOM 開始
- 問：「用完全不同的物理效應能達成嗎？」

### §4.3 SF 圖標準形式

```
S1（工具） ──F（場）──▶ S2（物件）
診斷：無效 / 有害 / 不足 / 缺失
```

詳細 SF 機制見 DK-02 §5。

## §5 Step 2 — TC 識別 + 多 TC 路由

### §5.1 單一 TC 流程

```
改善/惡化描述
  → 39 參數映射（KB 01）
  → 矩陣查表（KB 02）→ 候選原理編號
  → 原理具體化（KB 03）→ 2-4 候選方向
  → Step 3
```

KB 操作協議與品質檢查見 DK-02 §2。

### §5.2 多 TC 路由判定

```
Step 2 產出多個 TC
│
├─ 有明顯瓶頸 TC？（解了它，其他 TC 弱化或消失？）
│  ├─ 是 → 瓶頸路徑
│  │      只對瓶頸做 Step 3
│  │      Step 4 驗證其他 TC 是否真弱化
│  │      未弱化 → 切換 SIM
│  │
│  └─ 否（TC 獨立無主從）
│     └─ SIM 路徑：Step 2b → Step 3 → Step 3b → Step 4
```

**選擇依據**：瓶頸路徑更快（只解一個），SIM 路徑更全（評估所有交互）。不確定時選瓶頸路徑先試。

### §5.3 瓶頸路徑

| 排序原則 | 說明 |
|:---------|:-----|
| 關鍵瓶頸優先 | 解了它，其他矛盾隨之弱化 |
| 核心物理衝突優先 | 對最本質物理參數做 PC 深挖 |

實務上 TC/PC/SF 是 **1 對多** 的關係。**不需要解所有矛盾。**

### §5.4 SIM 路徑 — Step 2b OZ/OT 預篩

預篩兩個檢查：

**TC 去重**（定義期迴圈攔截）：

| 條件 | 動作 |
|:-----|:-----|
| OZ + OT + Px 全重疊 | 同一 PC 的正反面 → 合併 |
| TC-i 惡化 = TC-j 改善 | 高機率同 PC → 驗證後合併 |
| 部分重疊或不確定 | 保留為獨立 TC |
| 不重疊 | 確定獨立 |

**候選解法粗篩**：

| 條件 | 標記 |
|:-----|:-----|
| 不同 OZ 或不同 OT | 中性（無衝突） |
| 相同 OZ 且相同 OT | 潛在衝突（待精篩） |

只評跨 TC 的候選對。SIM 評分機制見 DK-02 §7。

### §5.5 矛盾迴圈診斷

迴圈（解 A 惡化 B → 解 B 惡化 A）**不是新問題類型，是 TC 定義不完整的信號**。

```
偵測到迴圈
├─ 兩矛盾的 OZ/OT/Px 重疊？
│  ├─ 是 → 其實是同一個 PC → 重新提取 Px
│  └─ 否 → 兩個獨立 TC → 回瓶頸排序
└─ Px 已找到但分離全部不可行 → §9 喊停
```

## §6 Step 3 — PC 深挖 + 分離 + SF

### §6.1 OZ-OT 鎖定 Px

| 步驟 | 問題 |
|:-----|:-----|
| OZ | 衝突發生在哪個位置？ |
| OT | 衝突發生在什麼時間？ |
| Px | 在 OZ × OT 內，哪個物理特性是兩難根源？ |

Px 提取流程與 Px 找不到三情境（長鏈耦合 / 多變數共控 / 非物理耦合）見 DK-02 §3。

### §6.2 PC 造句驗證

```
若 Px = A，則 P1 成立但 P2 出現問題；
若 Px = ¬A，則 P2 成立但 P1 出現問題。
```

填得出造句 = Px 邏輯自洽。**注意**：邏輯自洽 ≠ 物理正確；最終驗證在 Step 4 透過實驗確認。

### §6.3 分離原理選擇

| 分離類型 | 觸發問題 |
|:---------|:--------|
| 時間 | A 與 ¬A 在不同時間出現？ |
| 空間 | A 與 ¬A 在不同位置需要？ |
| 條件 | A 與 ¬A 在不同條件下需要？ |
| 系統層級 | 整體要 A，局部可以 ¬A？ |

每個候選分離策略用**第一性原理三問**驗證（控制方程？邊界條件？跨域實例？）。詳見 DK-02 §4。

### §6.4 SF 標準解 + 科學效應

依 SF 診斷狀態路由到 76 標準解 5 大類，結合分離策略篩選，導入科學效應產出具體 F + S。詳見 DK-02 §5-6。

### §6.5 產出格式

```
方案：[簡述]
├── F（場）：[具體場類型 + 控制方程]
├── S（物質）：[具體材料 + 物性]
├── OZ：[作用位置]
├── OT：[作用時機]
├── 分離策略：[類型 + 邊界條件]
└── 標準解編號：[Class X.Y.Z]
```

**品質門檻**：至少有一個方案的 F 和 S 能寫出具體數值（例「B_gap > 0.3T」），不是純定性（「磁場要夠強」）。

## §7 Step 4 — 驗證 + 複雜度

### §7.1 驗證項目

| 項目 | 量測 | 判定 |
|:-----|:-----|:-----|
| Px 分離成功 | P1 / P2 量測值 | P1 達標 + P2 不超基線 |
| 無新增有害作用 | 重做 Step 1 FA+SF | 無新紅線 |
| 複雜度通過 | 四問（§7.2） | 非補丁，或補丁已記錄 |
| 分離邊界內 | 邊界參數 | 工況在範圍內 |

### §7.2 四問複雜度

| 問題 | 補丁信號 | 進化信號 |
|:-----|:---------|:---------|
| 1. 零件變多？ | 是 | 否 |
| 2. 能量消耗變大？ | 是 | 否 |
| 3. 別人理解時間變長？ | 是 | 否 |
| 4. 符合演化趨勢？ | 否 | 是 |

**判定規則**：問題 1-3 兩個「是」，或問題 4「否」→ 補丁。

### §7.3 補丁不是失敗

```
判定為補丁
├─ 時間/成本允許重新深挖 → 回 Step 3
└─ 不允許 → 有意識地選擇補丁：
   1. 記錄為「已知技術債」
   2. 標記哪個 PC 未真正解決
   3. 排入下一代 TRIZ 待辦
   4. 繼續出貨
```

> **失敗不是選擇補丁，而是把補丁當永久方案卻不記錄。**

技術債登記簿格式見 DK-04 §6。

### §7.4 新方案引入新 TC

```
新 TC 與原 TC 形成迴圈 → §5.5 迴圈診斷
獨立新 TC → 回 Step 1（螺旋上升）
```

## §8 Step 5 — 工程輸出 + TR0 銜接

驗證通過後將 TRIZ 產出轉為工程交付物。

### §8.1 工程規格書（9.1）

| TRIZ 產出 | 工程規格 | 範例 |
|:----------|:---------|:-----|
| F（場） | 能量源規格 | 線圈匝數 / 電流 / 頻率 |
| S（物質） | 材料規格 | 牌號 / 熔點 / 潛熱 |
| OZ | 幾何規格 | 接觸面積 / 公差 |
| OT | 時序規格 | 頻率 / 佔空比 |
| 分離策略 | 設計約束 | 隔離距離 / 相容性 |

### §8.2 驗證計畫（9.2）

每個 Px 分離點對應一份驗證計畫，量測指標 + 判定標準 + 方法（原型實測 / FA 複查 / 環境測試）。

### §8.3 技術債登記簿（9.3）

補丁路徑必填，欄位見 DK-04 §6。

### §8.4 知識回饋（9.4）

回饋到專案知識庫（**非** TRIZ KB）：
1. 新發現的 TC/PC 模式
2. 有效的科學效應（含實測數據）
3. 失敗的分離策略
4. Proxy-Px 案例
5. SIM 交互發現（F/S 組合相容性）

### §8.5 TR0 銜接

Step 5 產出 = TR0 概念凍結的輸入：

| TRIZ 產出 | TR0 物件 | 落地位置 |
|:----------|:---------|:---------|
| 方案 F + S | Work Instruction (WI) | `docs/_harness/engineering/work_instructions/WI-NN_*.md` |
| S 物質 + 物性 | Material Card (MC) | `docs/_harness/engineering/material_cards/MC-NN_*.md` |
| 子系統介面 | Interface Control (ICD) | `docs/_harness/engineering/interface_control/ICD-NN_*.md` |
| 已知補丁 | 風險登記 | `docs/_harness/engineering/risk_register.md` |

TR1-TR10 銜接見 DK-04 §3。

## §9 STOP 信號 + 技術債原則

### §9.1 五個 STOP 信號

| 信號 | 判斷 | 動作 |
|:-----|:-----|:-----|
| 違反已知物理定律 | 能寫出具體哪條定律 | 喊停，重定義需求 |
| 找不到解但不確定是否物理不可能 | 寫不出被違反定律 | 暫停，標記知識邊界 |
| 理想度遞減 | Cost+Harm 增長 >> Function | 喊停 |
| 矛盾迴圈收斂失敗 | Px 找到但分離全不可行 | 喊停 |
| SIM 不收斂 | 2 輪後殘餘 -1 的 OZ/OT 仍重疊 | 喊停（架構層級重思） |

### §9.2 何時繼續衝

| 信號 | 說明 |
|:-----|:-----|
| 分離可行 | 時間或空間完美避開 |
| 跨代機會 | 科學效應庫中冷門效應可優雅替代 |
| 系統重分層 | 硬體 ↔ 軟體互換，物理絕境消失 |

### §9.3 早期預警

功能定義階段用矛盾矩陣預掃：兩個需求在 39 參數中屬「高難度衝突區」→ 提醒需破壞性創新預算。

### §9.4 系統演化方向（解法對齊）

優先對齊以下三條（其他產業需用完整 8 條重新篩選）：

1. **理想化提升**：功能增加，成本與危害減少
2. **向微觀演化**：宏觀結構解不了時 → 材料特性、微流體、量子效應
3. **增加動態性**：感測器讓系統根據狀態動態切換 SF 模型

完整 8 條（理想化 / 系統完整性 / 能量傳導 / 超系統 / 微觀 / 動態性 / 場演化 / 減人工）見 SSOT §8。
