## 1. 這頁要回答的一個問題

> 產品開發流程被重構成什麼樣子？為什麼不是多一套術語，而是根本性地重新定義開發主線？

## 2. 一句話 Key Message

> RDP-8 不是多一套流程術語，而是把產品開發拆成 8 種不確定性的依序消除——從「靠經驗跳躍」變成「可逐步驗證」。

## 4. 主要內容

### A. 8-Phase 主線

| Phase | 名稱 | 消除的不確定性 | 核心問題 | 方法 |
|:------|:-----|:-------------|:---------|:-----|
| **P0** | `SCOPE` | 問題不確定性 | 我們到底在解什麼問題？ | 5Why / KT Is-IsNot / CECA |
| **P1** | `MAP` | 系統不確定性 | 系統怎麼運作？哪裡有功能缺陷？ | FA + SF 功能建模 |
| **P2** | `RESOLVE` | 解法不確定性 | 矛盾怎麼解？有沒有不妥協的方案？ | TC→PC→SF 推理管線 |
| **P3** | `SPECIFY` | 規格不確定性 | 概念能不能凍結成可執行規格？ | 4-Q 複雜度檢查 + WI/MC/ICD 產出 |
| **P4** | `PROVE` | 物理不確定性 | 模擬結果是否支持設計？ | FEA / CFD 驗證 |
| **P5** | `BUILD` | 整合不確定性 | 組裝起來能不能運作？ | Alpha 原型 + V-test |
| **P6** | `HARDEN` | 製程不確定性 | 工廠能不能穩定地做出來？ | DFM / Process FMEA / Control Plan |
| **P7** | `SCALE` | 規模不確定性 | 量產能不能釋放？ | Cpk / DVP&R / PPAP |

### B. 分水嶺：G3 / TR0 / Concept Frozen

| 面向 | G3 之前（發明性前端） | G3 之後（工程性後端） |
|:-----|:--------------------|:--------------------|
| **驅動引擎** | TRIZ 推理引擎 | TR Gate 工程引擎 |
| **變更成本** | 改想法（低成本） | 改模具/製程（高成本） |
| **狀態管理** | `.triz-state.json`（session 級） | `.tr-state.json`（專案級） |
| **核心交付物** | 矛盾分析、解法概念、evidence | WI/MC/ICD → gate review → 測試報告 |
| **回溯代價** | 重跑 session（分鐘級） | 重開模/重製（週～月級） |

### C. Cost-of-Change 曲線概念

```
成本
 ↑
 │                                          ╱
 │                                        ╱
 │                                      ╱
 │                              ┃     ╱     ← P4-P7：改一次 = 重做實體
 │                              ┃   ╱
 │                              ┃ ╱
 │  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─╋─ ─ ─ ─
 │  ╱                           ┃         G3 分水嶺
 │╱   ← P0-P3：改一次 = 改文件  ┃
 ├──────────────────────────────┼──────────→ Phase
 P0   P1   P2   P3            G3   P4   P5   P6   P7
```

**關鍵洞察**：RDP-8 刻意把「最容易犯錯但改起來最便宜」的階段拆細（P0-P3 四段），讓問題在成本曲線左側被解決。

## 6. 口條骨架（30 秒）

> 中間這條線是 RDP-8，把產品開發拆成 8 個 phase，每個 phase 消除恰好一種不確定性。左半邊是發明性前端，用 TRIZ 引擎驅動，從問題定義一路走到概念凍結；右半邊是工程性後端，用 TR Gate 驅動，從物理驗證走到量產釋放。中間那條粗線是 G3——概念凍結——也是整條流程的分水嶺：G3 之前改的是想法，成本低；G3 之後改的是模具和製程，成本指數級上升。
