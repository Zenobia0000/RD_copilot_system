## 1. 這頁要回答的一個問題

> 為什麼這個系統值得當成**戰略基礎設施**投資，而不是另一個工程設計工具？

## 2. 一句話 Key Message

> **核心引擎 + 結構化知識庫 + 工具鏈 + 夥伴生態 = 工程設計領域的平台級基礎設施** — 系統不是工具而是**平台**；每多一個夥伴接入，全網價值遞增（網路效應），這是工具型產品做不到的。

```
║  L4  介面與生態夥伴                                            ║

║      • 下游：CAE / 品管 / PPAP / SOP / ERP 交付                 ║
║      • 跨領域：Domain KB 替換（mid-drive → 任意工程域）         ║
╠════════════════════════════════════════════════════════════════╣
║  L3  工具鏈與調度層                                            ║
║      • 14 個 Skills（6 TRIZ + 8 TR）                            ║

╠════════════════════════════════════════════════════════════════╣
║  L2  結構化知識庫                                              ║
║      • 39 工程參數 + 39×39 矛盾矩陣                             ║
║      • 40 發明原理 + 4 大分離原則                               ║
║      • 76 Su-Field 標準解                                       ║
║      • 6 類資產回寫迴路（決策 / 實驗 / 矛盾 / 失效 / 規則 / 最佳）│
╠════════════════════════════════════════════════════════════════╣
║  L1  核心引擎（雙核）                                          ║
║      • Auto-TRIZ：Step 0-5 發明性推理                          ║
║      • TR Engine：TR0-TR10 工程性驗證                          ║
║      • Gate G3 為分水嶺（TR0 概念凍結）                         ║
╚════════════════════════════════════════════════════════════════╝
```

**論述重點**：每一層都是**可被夥伴擴充的開放介面**：
- L1 雙核穩定不動（方法論層 SSOT）
- L2 知識庫可由各領域夥伴貢獻 Domain KB
- L3 工具鏈以 markdown skills 為主體，可擴增可審計
- L4 接入夥伴越多 → 全網價值越高

→ 與單一「工具」的封閉性（一個產品只解一個問題）形成本質差異。

### D. 為什麼是平台級基礎設施（網路效應 3 點）

#### D-1. 知識庫越用越強（資料網路效應）

```
專案 A 推理 ──► 決策 / 矛盾解 / 失效模式 ──► 回寫 KB
                                              │
                                              ▼
專案 B 啟動 ──► 讀取增強後 KB ──► 推理品質提升 ──► 回寫 KB
                                              │
                                              ▼
                                     ...遞迴強化...
```

每個專案的決策都自動回寫到 6 類資產 KB（決策記錄 / 實驗結果 / 矛盾解法 / 失效模式 / 設計規則 / 最佳實踐），下個專案推理品質自動提升。**這是工具型產品結構性無法擁有的特性**。

#### D-2. 工具鏈黏性（轉換成本）

接入後的下游交付物（SOP / PPAP / 品管文件）**自動從同一引擎產出**，遷移到競品意味著：
- 重建 22 份工程文件 schema
- 重建 6 類 KB 資產的歷史
- 重訓所有 TR/CAE/品管工程師流程

→ 遷移成本陡升，黏著度遞增。

#### D-3. 跨領域可複用（域擴展）

L2 結構化知識庫是 **domain-agnostic**：39 參數、矛盾矩陣、76 標準解適用於任何工程領域。從 mid-drive 馬達擴展到航太 / 醫材 / 半導體封裝，**只需更換 Domain KB（材料卡 + 領域案例）**，核心引擎與工具鏈完全重用。

| 對比 | 單一工具 | 本平台 |
|:-----|:---------|:------|
| 跨域成本 | 重新採購 / 重新訓練 | 只換 Domain KB |
| 知識累積 | 各專案孤島 | 全企業共用 |
| 夥伴接入 | 單向（被整合）| 雙向（雙方擴增）|
| 價值曲線 | 線性（每多一個用戶 +1）| 網路效應（n² 成長）|

## 5. 收束陳述

> **工具與平台的差別不在功能多寡，而在於擴張的方向**：工具靠功能堆疊吸引用戶（線性成長）；平台靠**網路效應吸引夥伴**（指數成長）。
>
> 這套系統從 Day 1 就以平台架構建構：L1 雙核穩定 / L2 知識庫可貢獻 / L3 工具鏈可擴增 / L4 介面標準化。當夥伴接入到第 N 個時，全網價值已不可被任何單一夥伴複製或取代 — **這就是戰略基礎設施投資的核心邏輯**。
