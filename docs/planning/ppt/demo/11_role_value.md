# 11 — 分眾價值

## Slide 標題

**不同角色都用得上 — 各自拿自己最關心的那一塊**

---

## Speaker Notes

> 系統不是只服務 RD 工程師，每個角色都拿到自己關心的那一塊資訊。PM 看可行性與時程；機構 RD 拿到矛盾解法與佐證；主管看 Gate 通過率與風險登記；製造工程師收到 DFM 審查；品保拿到驗證計畫。同一份 session 的輸出，依角色分流，不需要重新轉譯。

**過場到下一頁**：「如果這對你的工作有用，我們最後三步就可以開始試⋯」

---

## 視覺布局

- **排版**：5 張等寬角色卡片，水平排列（或 2+3 排版視螢幕比例）
- **每張卡片結構**：
  - 上：角色 icon + 名稱
  - 中：他關心什麼（一句）
  - 下：系統給他什麼（一句）
- **配色**：5 張用同一色系深淺變化，避免突顯某一個
- **底部**：一行「同一份 TRIZ session 的輸出，自動分流給 5 種角色」

---

## 重點內容

| 角色 | 關心什麼 | 系統給的東西 |
|:-----|:---------|:------------|
| 📋 **PM** | 這專案會不會延、會不會跑掉？ | Gate 通過率、關鍵路徑、風險登記 |
| 🔧 **機構 RD** | 這個矛盾真的能同時解嗎？怎麼解？ | TRIZ 矛盾分析、解法卡、佐證來源 |
| 👔 **RD 主管** | 該批准進 CAD 嗎？評審依據是什麼？ | Gate P 五維評估、CCI 複雜度評分 |
| 🏭 **製造工程** | 這個設計做得出來嗎？工序累積了嗎？ | DFM 審查報告、Process FMEA |
| ✅ **品質工程** | 哪些是 KC？怎麼驗證？ | KC List、驗證護照、SPC/Cpk 規劃 |

> 💡 **核心優勢**：同一份 session 輸出 → 5 個角色自動分流 → 不需要重複會議轉譯
