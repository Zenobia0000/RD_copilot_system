## 1. 概述

### 1.1 系統目的

RD Design Copilot 是一套 AI 驅動的早期概念設計決策平台。它將 SCAMPER/TRIZ 發散思考、KT Decision Analysis 收斂決策、以及 8-Gate 證據驅動流程整合在一起，幫助你在 Pre-CAD 階段做出信心可量化、決策可追溯、知識可沉澱的設計決策。

簡單來說：**在畫 CAD 之前，先把問題想清楚、方案探夠、風險看透。**

### 1.2 目標使用者

| 角色 | 主要用途 |
|------|---------|
| **RD 工程師** | 日常概念設計、問題分析、方案探索 |
| **RD 主管** | 設計審查、決策簽核 |
| **PM** | 需求對齊、進度追蹤 |

### 1.3 前置條件

- 瀏覽器：Chrome / Edge / Firefox（最新版）
- 已取得系統帳號（由管理員於 Supabase 後台建立）
- 網路可連線至部署伺服器

### 1.4 系統流程總覽

整個設計流程分為三大階段，由 8 個 Gate 控制品質關卡：

```
Phase 1: Define（定義問題）
  Brief → Explore → Gate 1.1 / 1.2 / PG1
        ↓
Phase 2: Diverge（發散探索）
  Track → Create → Pre-CAD Review → Gate 2.1 / 2.2 / PG2
        ↓
Phase 3: Converge（收斂決策）
  Design Review → Decision Record → Gate 3.2 / PG3
        ↓
  知識沉澱 → 完成
```

## 2. 快速入門

### 2.1 登入系統

1. 開啟瀏覽器，前往系統網址。
2. 在登入頁面輸入你的 Email 和密碼。
3. 如果是第一次登入，點擊「註冊」建立帳號。
4. 忘記密碼？點擊「重設密碼」，系統會寄送重設連結到你的信箱。

### 2.2 建立第一個專案

1. 登入後會進入 **專案列表頁** (`/projects`)，這裡列出你所有的專案。
2. 點擊右上角的「新建專案」按鈕。
3. 輸入專案名稱和簡短描述，按下「建立」。
4. 系統會自動導向該專案的 **Dashboard**。

### 2.3 認識 Dashboard

Dashboard (`/projects/:id`) 是你的專案儀表板，一眼掌握全局：

- **Phase 進度條**：顯示目前處於 Phase 1 / 2 / 3 的哪個階段。
- **Quick Stats**：矛盾數、假設數、方案數等關鍵指標。
- **Gate Donut**：8 個 Gate 的通過/未通過狀態圓餅圖。
- **KPI 卡片**：專案 KPI 即時數值與狀態。
- **矛盾收斂卡**：追蹤矛盾解決進度。
- **導覽卡片**：快速跳轉到各個工作頁面。

左側 **Sidebar** 列出所有可用頁面，你可以隨時切換：
Dashboard / Brief / Explore / Track / Create / Pre-CAD / Review / Decide / Feynman

### 2.4 你的第一個 Brief

1. 在 Dashboard 點擊「Brief」導覽卡，或從 Sidebar 點擊 Brief。
2. 填寫任務定義（詳見 Phase 1 說明）。
3. 完成後繼續進入 Explore 頁面。

整個流程建議照順序走：**Brief → Explore → Track → Create → Pre-CAD → Review → Decide**。但系統不會強制你的操作順序，只有 Gate 會在階段轉換時檢查。

## 3. Phase 1: Define — 定義問題空間

Phase 1 的目標是把問題定義清楚：你要解決什麼問題？有哪些約束？存在什麼矛盾？

### 3.1 Brief 頁面 — 任務定義

**路徑**：Sidebar > Brief（或 `/projects/:id/brief`）

#### 操作步驟

1. **Mission（任務描述）**
   - 在最上方的文字框輸入你的設計任務描述。
   - 例如：「設計一款輕量化的電動自行車車架，需承受 150kg 載荷」。
   - 寫完後點擊「AI 生成任務定義」按鈕，系統會自動產出結構化的 5W1H 任務定義。

2. **Hard Constraints（硬約束）**
   - 在 Constraints 表格中新增不可妥協的約束條件。
   - 每條約束需填寫：約束代碼、描述、類型（Hard/Soft）。
   - 點擊「AI 建議約束」按鈕，系統會根據你的 Mission 自動建議可能的約束。

3. **KPI 列表**
   - 新增你要追蹤的關鍵績效指標。
   - 每個 KPI 需填寫：名稱、目標值、單位、量測方法。
   - 點擊「AI 建議 KPI」按鈕，系統會根據任務描述建議合適的 KPI。

4. **素材上傳**
   - 拖曳或點擊「上傳區域」，可上傳相關參考文件。
   - 系統會自動從上傳檔案中擷取約束和 KPI。

5. **儲存**
   - 系統會自動儲存你的修改（右上角會顯示儲存狀態）。
   - 你可以隨時回來修改。

#### Gate 1.1 通過條件

頁面右側會顯示 Gate 1.1 的 Checklist，需要滿足：
- Mission 已填寫
- 至少 3 個 KPI，且每個都有量測方法

### 3.2 Explore 頁面 — 探索問題空間

**路徑**：Sidebar > Explore（或 `/projects/:id/explore`）

Explore 頁面有三個 Tab，分別對應三個子步驟：

#### Tab 1: Socratic（蘇格拉底問答）

AI 會從七個類別向你提問，幫助你深入思考問題的各個面向：

1. 點擊「AI 生成提問」按鈕，系統會產出一批問題。
2. 逐一回答每個問題，在問題下方的文字框輸入你的答案。
3. 你也可以手動新增自己想到的問題。
4. 已回答的問題會標記為完成（綠色勾勾）。

七類提問涵蓋：功能、結構、介面、製程、成本、壽命、環境等面向。

#### Tab 2: Contradictions（矛盾識別）

基於你在 Socratic 問答中的回答，系統會自動識別技術矛盾：

1. 點擊「AI 識別矛盾」，系統會分析你的答案並列出潛在矛盾。
2. 每條矛盾會標示類型：TC（技術矛盾）、PC（物理矛盾）、SF（物質場）。
3. 你可以手動新增矛盾，或編輯 AI 識別的結果。
4. 對重要矛盾點擊「正式化」，將其轉為 TRIZ 標準格式。

#### Tab 3: CLD（因果環路圖）

將矛盾之間的因果關係視覺化：

1. 系統會根據已識別的矛盾自動生成因果環路圖。
2. 圖中的節點代表設計參數，連線代表因果關係。
3. 你可以在圖上標記「斷路點」— 這些是最有潛力用 TRIZ 解決的地方。
4. 斷路點會自動帶入 TRIZ 原理提示。

#### Gate 1.2 通過條件

- 至少 10 個假設已被萃取
- 至少 3 個高風險假設已標記
- 至少 3 條矛盾已識別

#### Phase Gate 1（PG1）通過條件

- 至少 1 個 CLD 已建立
- 至少 3 個斷路點已標記
- 矛盾已正式化

通過 PG1 後，專案狀態會從 PHASE_1 轉為 PHASE_2。

## 4. Phase 2: Diverge — 發散與探索

Phase 2 的目標是盡可能多地產出候選方案，然後用硬約束篩選。

### 4.1 Track 頁面 — 假設追蹤

**路徑**：Sidebar > Track（或 `/projects/:id/track`）

Track 頁面管理你的所有假設，用看板（Kanban）方式追蹤每個假設的生命週期。

#### Tab 1: Kanban（假設看板）

1. 看板有四個欄位：**Open → Experimenting → Validated → Refuted**
2. 每張卡片代表一個假設，顯示來源、風險等級、驗證狀態。
3. 拖拉卡片到不同欄位，即可更新假設狀態。
4. 點擊卡片可展開詳情，編輯最壞後果、最小驗證方法等。

#### Tab 2: Unknown Factors（未知因子）

1. 列出尚未被假設覆蓋的未知因子。
2. 每個因子可填寫：等級、範圍描述、關聯假設。
3. 點擊「轉換為假設」，將未知因子轉為正式假設並加入看板。

### 4.2 Create 頁面 — 方案產生

**路徑**：Sidebar > Create（或 `/projects/:id/create`）

Create 是整個系統最核心的頁面，包含多個功能區塊：

#### Anti-Anchor（反錨定衝刺）

在頁面頂部，系統會提醒你打破思維慣性：

1. 點擊「生成非典型架構」，AI 會產出至少 1 個與你現有方案完全不同的替代架構。
2. 這些路線不一定實用，但能拓展你的思考邊界。
3. 你可以選擇採納、暫存或忽略。

#### TRIZ 三路徑求解

這是解決技術矛盾的核心引擎：

1. 從矛盾列表中選擇一條要解決的矛盾。
2. 點擊「TRIZ 求解」，系統會同時走三條路徑：
   - **TC 路徑（技術矛盾）**：映射改善/惡化參數 → 查矛盾矩陣 → 取得建議原理。
   - **PC 路徑（物理矛盾）**：識別物理矛盾 → 套用四大分離原理（時間/空間/條件/系統層級）。
   - **SF 路徑（物質場）**：建立物質場模型 → 對照 76 標準解。
3. 每條路徑會產出具體的解法方案，你可以逐一檢視、編輯、評分。

#### 子系統分解

1. 點擊「AI 建議子系統」，系統會根據你的任務描述分解出子系統架構。
2. 你也可以手動新增子系統。
3. 每個子系統可設定：名稱、描述、介面鄰居、六維介面契約（包封/載荷/訊號/熱/基準/維修）。

#### SCAMPER 發散

對每個子系統進行七種創意動作：

1. 選擇一個子系統。
2. 點擊「SCAMPER 發散」，系統會為每個動作（Substitute / Combine / Adapt / Modify / Put to other uses / Eliminate / Rearrange）生成變形方案。
3. 如果 SCAMPER 變形產生了新的矛盾，系統會自動回饋到矛盾列表，形成閉環。

#### 方案集合 + MUST 篩選

1. 所有產出的解法會匯集成方案卡片。
2. 每張方案卡顯示：機制描述、假設、風險、穩健性評分。
3. 點擊「MUST 篩選」，系統用 6 條硬約束（M1-M6）逐一檢查每個方案：
   - 結果為 **Go**（通過）或 **No-Go**（淘汰）。
   - 任何一條 MUST 失敗，該方案即被淘汰。

#### Gate 2.1 通過條件

- 至少 3 個高風險假設各有對應的實驗計畫

#### Gate 2.2 通過條件

- 至少 3 個方案通過 MUST 篩選

### 4.3 Pre-CAD Review 頁面

**路徑**：Sidebar > Pre-CAD（或 `/projects/:id/pre-cad`）

在進入 CAD 繪製之前，對通過 MUST 的候選方案做五維度審查：

1. **方案列表**：頁面上方顯示所有通過 MUST 的候選方案。
2. **五維評分**：對每個方案的五個維度打 1-5 分：
   - 空間約束：方案是否符合現有空間與尺寸限制
   - 解耦程度：方案是否與其他子系統充分解耦
   - 可驗證性：是否有可在 Pre-CAD 階段驗證的最小實驗
   - 主要風險：關鍵風險是否已識別且可控
   - 最小 CAD 工作量：進入 CAD 階段所需的工作量是否合理
3. **AI 分析**：點擊「AI Analyze」，系統會自動分析並給出各維度評分建議，附帶引用來源。
4. **矛盾收斂統計**：頁面會顯示 Fatal / Major / Minor 矛盾的解決進度和信心分數。
5. **約束可行性**：從 Brief 帶入的約束清單，標示每條約束的驗證狀態（已驗證/存疑/不可行）。
6. **雷達圖**：將五維評分用雷達圖視覺化，方便比較方案。

#### Phase Gate 2（PG2）通過條件

- 至少 1 個方案的 Pre-CAD 審查通過（overall_pass = true）

通過 PG2 後，專案狀態會從 PHASE_2 轉為 PHASE_3。

## 5. Phase 3: Converge — 收斂與決策

Phase 3 的目標是基於證據做出最終決策，留下完整的決策記錄。

### 5.1 Design Review 頁面 — 證據審查

**路徑**：Sidebar > Review（或 `/projects/:id/review`）

Design Review 頁面有三個 Tab：

#### Tab 1: Evidence（證據矩陣）

1. 表格呈現「假設 x 證據」的交叉矩陣。
2. 每個格子的顏色代表證據等級：
   - **E0**（灰）：無數據
   - **E1**（淺藍）：專家意見/文獻
   - **E2**（藍）：模擬/分析
   - **E3**（深藍）：原型測試
   - **E4**（綠）：量產驗證
3. 點擊格子可新增或更新證據。
4. 目標是讓所有高風險假設至少達到 E2 以上。

#### Tab 2: Risks（風險登錄）

1. 以 FMEA 風格管理風險。
2. 每條風險填寫：描述、機率（P）、嚴重度（S）。
3. 系統自動計算風險分數（P x S）並分級：L / M / H / H*。
4. 你可以新增風險、關聯到特定方案或假設。

#### Tab 3: Experiments（最小實驗）

1. 為高風險假設設計最小實驗。
2. 每個實驗填寫：目的、方法、預期結果、實際結果。
3. 實驗完成後更新證據等級，形成閉環。

### 5.2 Decision Record 頁面 — KT 決策

**路徑**：Sidebar > Decide（或 `/projects/:id/decide`）

Decision Record 是最終決策頁面，用 KT（Kepner-Tregoe）Decision Analysis 框架做方案評選：

#### Step 1: MUST 快篩結果回顧

頁面上方回顧所有方案的 MUST 篩選結果，不通過的方案已被排除。

#### Step 2: WANT 標準評分

1. 系統預設 6 條 WANT 標準（W1-W6），你可以修改或新增。
2. 為每條 WANT 設定權重（1-10）。
3. 對每個候選方案在每條 WANT 上打分（1-10）。
4. 系統自動計算加權分數（Weighted Score = 權重 x 得分）。
5. 可用長條圖或雷達圖比較各方案的綜合得分。

#### Step 3: Adverse Consequences（不利後果分析）

1. 為排名最高的方案列出可能的不利後果。
2. 每條不利後果評估機率和嚴重度。
3. 系統計算風險等級，幫助你判斷「最高分的方案是否風險可控」。

#### Step 4: 簽核

1. 確認選定方案後，填寫決策理由。
2. 邀請相關人員簽核（RD 主管、PM 等）。
3. 簽核完成後產出 Decision Record。

#### Step 5: Action Items

1. 決策通過後，列出後續行動項目。
2. 每個 Action Item 可設定負責人和預計完成日。

#### Step 6: 匯出

點擊「匯出」按鈕，可下載 Markdown 或 JSON 格式的完整決策報告。

#### Gate 3.2 通過條件

- Decision Record 已完成簽核
- 所有 WANT 標準都有證據支撐

#### Phase Gate 3（PG3）通過條件

- 所有核心工件（Brief、矛盾分析、方案評選、決策記錄）狀態為 Released

通過 PG3 後，專案狀態會標記為 COMPLETED。

## 6. Knowledge Base — 知識庫與 Feynman 學習

### 6.1 知識回寫

在整個設計流程中，系統會自動沉澱六類知識資產：

| 類型 | 說明 |
|------|------|
| 決策記錄 | 最終決策的理由、備選方案、否決原因 |
| 實驗結果 | 最小實驗的設計與結論 |
| 矛盾解法 | TRIZ 解法的具體應用 |
| 失效模式 | 發現的風險和失效模式 |
| 設計規則 | 從專案中歸納出的設計規則 |
| 最佳實踐 | 成功的做法和流程改善 |

### 6.2 Knowledge Base 頁面

**路徑**：Sidebar > Knowledge Base（或 `/knowledge-base`）

跨專案的知識搜尋介面：
1. 在搜尋框輸入關鍵字，搜尋所有歷史專案的知識資產。
2. 點擊搜尋結果可查看完整引用和上下文。
3. 在設計過程中，各頁面右側的「知識參考面板」(Knowledge Refs Panel) 會自動帶出相關的歷史知識。

### 6.3 Feynman 學習頁面

**路徑**：Sidebar > Feynman（或 `/projects/:id/feynman`）

以 Feynman 學習法幫助你內化設計知識：
1. 頁面列出本專案的所有知識資產。
2. 每個資產有三種狀態：Pending（待處理）→ Written（已寫入）→ Reviewed（已複核）。
3. 點擊「AI 解說」，系統會用白話重新解釋這條知識，幫助你確認自己是否真正理解。

## 7. 常見問題 FAQ

### Q1: Gate 沒有通過怎麼辦？

Gate 不通過代表某些必要條件尚未滿足。回到對應的頁面補齊缺少的項目即可。例如 Gate 1.1 需要至少 3 個 KPI 且有量測方法，回到 Brief 頁面補上就好。系統不會鎖住你的操作，Gate 只是提醒你「還有東西沒做完」。

### Q2: AI 生成的結果不好怎麼辦？

所有 AI 生成的內容（任務定義、矛盾識別、TRIZ 解法等）都可以手動編輯。AI 是輔助工具，最終判斷權在你手上。如果 AI 結果品質不佳，建議：
- 檢查你的 Mission 描述是否夠清楚。
- 補充更多 Socratic 問答的回答。
- 手動修正後再重新生成。

### Q3: 可以跳過某個步驟直接進入下一個 Phase 嗎？

技術上你可以自由瀏覽任何頁面，但 Phase Gate 會在階段轉換時檢查。如果 PG1 的條件沒滿足，專案狀態不會進入 Phase 2，這代表 Phase 2 的某些功能可能缺少上游資料。建議按順序完成以確保資料完整性。

### Q4: 資料會自動儲存嗎？

是的。大部分頁面的修改會自動儲存到資料庫。你可以從右上角的儲存狀態指示器確認。重新整理瀏覽器或關閉後重開，資料都會保留。

### Q5: 如何多人協作？

目前 v1.0 支援多人登入同一專案，資料即時同步到資料庫。但請注意，同時編輯同一筆資料時，後儲存的會覆蓋先儲存的。建議團隊成員分工負責不同的頁面或步驟。
